# News snapshot and deployment

`python3 scripts/refresh_news.py` collects attributed publisher headlines, links and dates into `edition/data/news.json`. It does not ingest article text or images. A wholly failed refresh keeps the previous items and generation time and records an unavailable attempt; a partial refresh retains recent items from failed sources and reports `partial`. Entries older than 24 days are excluded from a successful refresh. Labels are inferred from headline keywords and are not fact checks.

`news-snapshot.yml` runs the collector on a schedule and commits the snapshot to `main`, allowing a Git-connected build of that branch to consume it. Scheduled GitHub Actions run from the default branch, so the workflow must first be reviewed and merged there. The current observed Vercel production build was sourced from `feature/tohesar-beauty-project-014`, not `main`. **Consequently, this workflow alone does not establish automatic updates on the current production deployment.** Before enabling the new newsroom in production, verify the Vercel project's production branch, custom-domain assignment and Git integration, then select a reviewed deployment arrangement that actually builds the refreshed snapshot. Do not point this workflow at an operating branch without that verification. The older Pages workflow refreshes only its Pages artifact, not the Vercel deployment.

As observed on 29 October 2026, Porsche and Motor1 responded successfully; the configured BMW RSS endpoint redirected to an HTML newsroom outside the permitted host. Its source is therefore marked unavailable rather than presented as live. Restore it only after identifying and validating a publisher feed.
