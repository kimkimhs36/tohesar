# VISION DRIVE 4.1 영상 개선 작업

이 폴더는 VISION DRIVE 4.0 원본 ZIP을 건드리지 않고 만든 별도 작업본이다.
4.1은 실제 ESP32용으로 빌드되었으나, 아직 실제 보드에 설치하거나 검증하지 않았다.

- PSRAM이 있을 때 JPEG 버퍼 두 개로 연속 촬영하고, 새 읽기 전용 MJPEG 스트림을 로봇 전용 Wi-Fi의 82번 포트에 제공한다.
- PSRAM이나 스트림이 준비되지 않거나 연결이 끊기면 X4 Studio는 기존 81번 포트의 사진 요청 방식으로 돌아간다.
- 기존 80번 포트의 인터페이스와 조종 잠금, 81번 포트의 사진 경로를 유지한다. 스트림만으로는 기존 조종의 카메라 신선도 조건을 채우지 않는다.
- 카메라 버퍼의 촬영 시작 시각을 확인해 오래된 프레임은 내보내지 않는다. 이 시각은 로봇 기준의 프레임 나이이며 무선 전송과 화면 표시를 포함한 전체 지연은 아니다.
- 로봇이 보낸 프레임 수·평균 송신 속도·촬영 대기와 PC가 받은 속도를 구분한다. 4.0에는 장치 송신 진단값이 없으므로 빈 칸으로 표시한다.
- VISION DRIVE 자체 화면은 디코딩한 실제 수신 FPS를 표시한다. 녹화는 새 수신 프레임으로 갱신하고 최대 30fps로 저장한다. 실제 프레임이 8fps면 없는 장면을 만들어 30fps로 바꾸지는 않는다.
- PC용 X4 Studio에는 프레임 요청 속도 개선과 스트림 수신이 추가되었다. 실행 중인 프로세스에는 재시작 후 적용된다.
- 합성 로컬 MJPEG 30fps 입력은 수신부에서 약 29.8fps로 측정됐다. **실제 ESP32와 Wi-Fi에서 30fps를 달성했음을 뜻하지 않는다.**
- 실제 ESP32용 컴파일과 모의 HAL 36개 시나리오를 통과했다. 타임스탬프가 오래된 프레임 거절과 스트림 오류 시 프레임 버퍼 반환을 포함한다. 가짜 영상과 브라우저 환경으로 FPS 표시, 녹화, 영상 중단 후 자원 정리도 확인했다. 모의 검사는 실제 배선이나 모터의 시험이 아니다.

참고한 오픈소스: [Espressif esp32-camera 설명서](https://github.com/espressif/esp32-camera/blob/master/README.md)와
[Espressif CameraWebServer 예제](https://github.com/espressif/arduino-esp32/blob/master/libraries/ESP32/examples/Camera/CameraWebServer/app_httpd.cpp).
JPEG 다중 버퍼의 지속 캡처와 MJPEG 전송 방식을 참고했다. 다중 버퍼는 CPU와 메모리 부담이 늘 수 있다.

## 설치 준비 상태

`release/firmware.bin`은 앱 전용 이미지, `release/manifest.json`은 크기와 해시 기록이다.
설치 전에 정확한 보드의 4MB 플래시를 별도 BIN과 JSON으로 백업하고 읽기 검증해야 한다.
백업에는 비공개 설정이 포함될 수 있으므로 외부에 공개하지 않는다.

설치 스크립트는 백업의 보드 MAC과 해시를 확인하고, 기존 파티션 표가 빌드와 정확히 같을 때만
기존 VISION-DRIVE Wi-Fi 이름의 끝 네 자리와 보드 MAC도 대조한다. 일치하면
0x10000 앱 영역에 쓰고 읽기 검증한다. 설정 영역, 부트로더, 파티션 표를 덮어쓰지 않는다.
원상 복구는 같은 보드의 전체 백업이 필요하다.

보드를 설치 모드로 연결하기 전 모터 전원을 끄고, 연기나 불꽃이 났던 손상 부품이
아직 포함되어 있지 않은지 확인한다. 현재 라이다 COM12를 ESP32 업로드 대상으로 사용하지 않는다.
이후 실물 설치와 측정은 별도로 확인해야 한다.
