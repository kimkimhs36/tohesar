# 검증 기록 / 2026-11-02

## 확인된 범위

- **컴파일:** PlatformIO `espressif32@6.9.0`, Arduino ESP32 2.0.17, `esp32cam`, huge_app, 4 MB flash. 실제 Xtensa 툴체인으로 `firmware.bin`과 0x0 오프셋 합본을 빌드했다. 크기·SHA-256은 `release/build.log`, `release/manifest.json`을 따른다. 이미지 체크섬은 esptool image_info에서 확인했다.
- **기기 안전 상태 머신:** 실제 `firmware/include/control.h`를 호스트 C++로 실행해 만료 경계, millis 오버플로, 순서 역전, 이전 토큰, 범위 이탈, 영상 만료와 수동 재준비를 시험했다.
- **실제 HTTP 핸들러와 모터 출력 경로:** `firmware/src/main.cpp` 자체를 모의 ESP32 HAL에서 실행해 입력 검증, GPIO 채널·극성, 방향 전환 중 브리지 입력 0, LED, 만료 처리 등을 확인했다. 안전 태스크 초기화 실패를 포함한 29개 시나리오와 무작위 좌우 PWM 3,000개를 포함한다. 이는 전기 신호·모터·FreeRTOS 스케줄 실측이 아니다.
- **화면 및 조작:** Chromium과 WebKit 엔진에서 데스크톱, iPad 가로 1194×834·1024×768, iPad 세로, 모바일 390×844·320×740 및 844×390을 렌더링하고 조이스틱, 키 해제, STOP, 오류·지연·시뮬레이션 네트워크 분리를 확인했다. WebKit은 데스크톱 환경의 엔진 시험이며 실제 iPad Safari·Wi-Fi 시험이 아니다. 결과 JSON과 스크린샷은 `release/`, `screenshots/`에 있다.
- **최초 서비스 도구:** 실제 esptool-js 명령과 합성 시리얼 패킷으로 전체 플래시 읽기, ACK, 최종 MD5와 실패 처리를 시험했다. 별도의 모의 로더로 브라우저 포트 선택, 백업 파일 다운로드, 해시 확인, 설치 및 복원 차단·읽기 확인 등 26개 검사를 시험했다. 실제 USB·부트 진입·플래시 쓰기는 미시험이다.
- **Wi-Fi와 좌우 보정:** 합성 지연·오류·영상 중단에 대한 네트워크 시험 12개와, 수동 보정·차동 혼합의 1,107개 조합을 통과했다. 상세 결과는 `release/` 테스트 로그를 참고한다. 실제 Wi-Fi의 프레임률, 신호 범위, 부드러움·지연 분포와 차의 궤적은 기기 없이 측정하지 않았다.

## 남은 실물 인수 시험

1. 제조사 배선과 전원을 확인하고 바퀴를 띄운다. 설치 도구에서 정확히 그 기기의 전체 정상 플래시를 백업·보관한 뒤 설치한다. 이 프로젝트 작업에서는 로봇을 연결하거나 플래시하지 않았다.
2. iPad Safari·스마트폰으로 AP 접속, 프레임의 실제 움직임, 전진/후진/좌우 모터 극성, LED, LOW/MID/HIGH, 사진/녹화를 확인한다.
3. 바퀴를 띄운 채 Wi-Fi를 완전히 꺼서 모터 출력 중단까지 시간을 외부 촬영한다. 350 ms는 마지막 유효 명령 후 펌웨어 만료 기준이며 실제 기계적 정지 시간의 보증이 아니다.
4. 바퀴 체결·마찰을 먼저 확인하고 수동 좌우 PWM 보정값을 LOW에서 조금씩 바꾸며 실제 직진을 관찰한다. 바닥, 배터리, 바퀴·모터 차이에 따라 보정값이 바뀐다. 피드백 센서가 없어 정렬·자세가 자동으로 유지된다고 보장하지 않는다.
5. 화면이 부드러운지는 실제 교실 전원과 거리에서 시각적으로 확인하고, 통신 진단의 HTTP 왕복 시간과 별개로 영상·물리 반응을 촬영한다. HTTP RTT는 카메라 지연이나 모터 지연의 대체 측정값이 아니다.
6. 해당 기기에서 저장한 BIN + JSON을 사용해 기존 펌웨어로 복원하고 제조사 영상·모터를 다시 확인한다. 실제 기기 백업은 아직 확보하지 못했다.
